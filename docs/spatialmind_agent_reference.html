SpatialMind Agent Reference

A spatial-omics agent whose defining behaviour is what it won't do. It ingests a Xenium section, runs real Scanpy and Squidpy analysis, and refuses to name a single cell type until a human has reviewed the labels. This is how that refusal is built, what it currently can and cannot do, and where the evidence for each claim comes from.

What it is

Most spatial-omics tooling will happily tell you that a cluster is astrocytes. It has no way to know that. Cluster identity is an expert judgement about tissue, and a pipeline that guesses it produces a figure that looks exactly like one that knows.

SpatialMind's design decision is to make that impossible. A validation gate sits between data preparation and biological inference. Until a human supplies expert_cell_labels.csv and cell_regions.csv at 70% coverage, the agent will run real analysis and describe data-derived groups — never cell types. Every claim it does make carries a reliability score, and every tool it could have used but cannot carries a reason.

Around that core sits SpatialMind Studio, a packaged macOS app, because the gate was unreachable in practice: clearing it meant hand-authoring a CSV of 40,887 cell IDs, which no pathologist will ever do.

The workflow

One bundle in, one of two lanes out. Which lane is not a setting — it is decided by whether reviewed evidence exists.

Architecture

Four entry points, one registry, one gate. The convergence is recent and is the most important structural property in the system.

Layers

Ingestion

Reads ~6 MB of a 2.5 GB bundle into one SpatialDataset contract. Keeps source counts and analysis values separate, and excludes QC pseudo-features from every expression matrix — left in, they dominate PCA and rank as top markers.

Tools

30 registered, each with a capability state. Scaffolds are detected from bytecode, so freezing the app cannot hide them. list_plannable() excludes them, so a planner cannot select a tool that does no work.

Claims

Every biological statement enters a ledger as supported, dropped or refused, and carries four evidence components combined by weakest link.

The six tiers

Read from the import graph, not from any docstring. Each tier depends only on tiers below it; nothing reaches upward.

What each tier is for

1 · Contracts ~860

SpatialDataset, SpotRecord, ToolResult, ToolCallSpec, BiologicalClaim. The vocabulary every tier speaks, which is why a Xenium bundle, an H5AD and a CSV all become the same object. Imports nothing else in the project — the moment the vocabulary imports a layer, every layer is coupled through it.

2 · Capability ~7,100

Things that can do work while knowing no workflow exists. ingestion reads ~6 MB of a 2.5 GB bundle into one contract and keeps source counts separate from analysis values; tools is the 30-tool registry with capability states; storage hashes run records for replay. None of them knows a gate exists.

3 · The gate 278

One file, one job: decide whether a tool may run. Deliberately thin and deliberately low, because every executing tier has to reach it. pilot_gate was moved here from pilot.xenium — that module imports agent.runtime, so an agent-layer caller would have closed a cycle. A contract pins it: reach upward from this file and the build fails.

4 · Derived products ~2,570

Results into artifacts: reports, figures, the explorer, the S/A/P/R reliability model, dataset governance manifests. Contracted as pure consumers — viz and storage may not import the agent or app, so rendering can never reach back and trigger analysis.

5 · Execution ~3,880

Where a plan becomes a run. agent holds the loop, the typed-plan validator and the claim-grounding checker; pilot is the validated Xenium path — gate, lanes, claim ledger, report generation — and at 3,065 lines the largest single unit in the codebase.

6 · Surfaces ~5,330

How a human or another program gets in: Studio, the FastAPI service, the CLI, the Celery worker, the expert-review packet builders. app is contracted as a top layer nothing else may import, so no lower tier can depend on the UI existing.

Three self-descriptions that disagreed. orchestrator.py said "six layers" and named the v1 set — ingestion, algorithms, reasoning, visualization, storage, memory — omitting tools, pilot, gatekeeper and app, two of the six it named being themselves legacy. __init__.py's __all__ listed fifteen names, flat. The import graph said the six tiers above. The most authoritative-sounding one was the most out of date; it has been corrected.

Review Studio, and why it opens in a second

Clicking a cell selects its whole 10x cluster; applying a Cell Ontology term writes every cell in that cluster. Dragging a rectangle names a region. Both merge into the bundle's tables rather than overwriting, so a second session cannot erase the first.

The map needs an id, a coordinate and a group — not expression. Reading cells.parquet plus the cluster table builds that index in 1.55 s using 97 MB, against 6.32 s and 507 MB for a full load: 4.1× faster, 5.2× lighter. The browser gets a display sample; selections resolve server-side over every cell, so coverage and the gate are computed on the whole section, not on what was drawn.

Choosing a tool — three routes, one object

Ask

A question routes to a typed plan with reasoning shown. Refuses and names the missing tool when only a scaffold could answer.

Recipes

Four saved plans: descriptive lane, validated pilot, spatial structure only, region contrast.

Tool Bench

The full catalog with preconditions and runtimes. Dependencies are inserted automatically; scaffolds cannot be selected.

All three produce the same ToolCallSpec list that the real validator checks before execution. Plan validation checks structure; whether the inputs exist is the gate's job — which is why a gate-blocked plan still validates as sound rather than inventing fake plan errors.

Reliability

Four evidence components, combined by weakest link — not averaged, because a missing evidence class should not average away.

ComponentAsksTypical
S_statisticalIs there a spatial statistic behind this?1.000
A_annotationHow complete and confident are the labels?0.862
P_panelDoes the panel measure the markers this claim needs?0.500–0.667
R_spatial_robustnessDoes it survive a graph-size sweep?0.964–1.000
The panel is the binding constraint on every claim. In three claims out of three, the limiting component was P_panel. A reviewer who labels every cell perfectly moves A to 1.0 and the reliability of those claims does not move at all. The brain panel measures 34 of 51 canonical markers — ceiling 0.67 — and GFAP, the canonical astrocyte marker, is not on it. Endothelial and stromal identification start at 0.33. Labelling buys which claims are possible, not how reliable they are.
Calibrated against controls that are actually run. Positive controls interleave two real cell-type names in stripes; negatives permute those same labels among the same cells. Matched on vocabulary, composition, coverage and pair count — everything but spatial arrangement. AUROC 0.975. Getting the match wrong first found a real bug: statistical strength took an unadjusted maximum over cell-type pairs, so more cell types bought more strength for free, and the null out-ranked implanted truth at AUROC 0.35. The fitted model is deliberately not deployed — only S varies in that design, 18 records over 4 features, no held-out split.

Predictions, not labels. The gate does not accept this file.

The malignant count is not a measurement. The same reference and the same algorithm call 955 or 71 of those 2,497 cells malignant, depending only on how the reference is sampled — a 13.5× swing with no change to the target data. A proportional draw keeps the atlas's own prior and lets the majority class dominate a neighbour vote; a stratified draw gives every class equal weight and discards that prior. Stratification is used because a class absent from the sample can never be assigned at all, which is the worse failure — but it is a trade, not a correction.
Loading it needed a streaming reader, for two silent reasons. anndata's backed mode covers X only, and this file's layers total 37 GB uncompressed, so a backed open was killed before sampling one cell — and the fallback was a full in-memory read, which is worse. And CELLxGENE keys var by Ensembl ID with symbols in feature_name, while a Xenium panel is symbols: reading the index gives an overlap of zero, which is not an error that announces itself but a confident answer computed from nothing. Reading the wanted rows through h5py: 2,000 cells in 7.8 s at 0.57 GB peak.

Packaging

Ships as a macOS .app — a WKWebView in a native window over a server bound to 127.0.0.1, dark chrome end to end, icon on Apple's template. Intel only. PyInstaller freezes installed wheels and 400 of 414 native extensions here are x86_64-only, so a universal binary cannot be produced from one machine. A CI matrix on macos-13 and macos-14 builds both; the arm64 half has not been run.
