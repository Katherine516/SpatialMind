The readWhat we are actually shipping

The engineering is done: ingestion, a strict Scanpy/Squidpy backend, a typed planner, a claim ledger, hashed replay. What is missing is not capability — it is a surface where a wet-lab scientist can meet the gate without a terminal. Today unblocking a dataset means hand-authoring a CSV of 40,887 cell IDs. No pathologist will ever do that.

So Studio has one job: turn the six gate conditions into work a human can finish in an afternoon. Review Studio is therefore the centre of the app, not a utility hanging off it. Everything else — the library, the planner, the tool bench, the report — is arranged around getting a dataset into that room and out the other side.

The second job is honesty at the surface. Eighteen of thirty registered tools are scaffolds that return a placeholder. They stay in the catalog, visible and disabled, because a user who discovers on their own that cnv_inference does nothing loses trust in the twelve tools that work.

The core askThree ways to choose a tool

Ask · default

The agent picks

Question in, typed plan out. Each step shows the tool, why it was selected, its dependencies, its lane, and its runtime. Nothing runs before you approve it. When no implemented tool answers the question, the agent says so instead of substituting a near-miss.

Recipes · guided

Pick a known lane

Four saved plans that map to what the repo already runs end to end: descriptive QC lane, validated Xenium pilot, reference-assist, healthy-vs-disease comparison. Same validator, same gate — you are choosing a starting plan, not a bypass.

Tool Bench · manual

Drive it yourself

The full catalog with capability, backend, runtime and preconditions. Select a tool, fill its parameters, add it to the plan. Dependencies are inserted for you and flagged; scaffolds cannot be selected at all.

All three converge on the same object — a typed plan the local validator checks before anything executes. That separation is the reason a hosted LLM can be allowed to propose plans at all: it suggests, the validator decides. Plan validation checks structure; the gate checks inputs. Keeping them apart is why a blocked run still shows a valid plan rather than inventing fake plan errors.

SequencingWhat ships when

v1 — the afternoon. Datasets, Readiness, Review Studio, Report. One dataset, one user, local. Success is a single scientist taking a bundle from blocked to a validated report without opening a terminal. Ask and Tool Bench ship read-only in v1: they show the plan the pilot would run, and cannot be edited yet.

v2 — the agent. Ask becomes interactive, Tool Bench becomes editable, recipes land. This is where hosted LLM planning is switched on, behind the same validator.

v3 — the lab. Multi-user is where the real work is, and the README already names the gaps: auth, dataset allowlists, job-queue hardening, audit logs. Review assignment and reviewer agreement belong here too — two reviewers labelling the same section is how the claim-truth set for a calibrated reliability model finally gets built.

RisksWhat could sink this

R1
Review is still too much work.

Even with a canvas, labelling 40,887 cells one population at a time may take longer than a reviewer will give. Mitigation: cluster-level assignment as the default unit (what the prototype does), ontology prefill, and the astrocyte-suggestion pass already in the repo. Measure median time-to-70%-coverage before building anything else in v2.

R2
The blocked state reads as a broken product.

Most first sessions end blocked. If that feels like failure, users churn before they ever see a validated report. Mitigation: the descriptive lane always returns something real on first run, and every blocker is phrased as a next action, never as an error.

R3
Reliability scores get read as accuracy.

A 0.62 is a weakest-link floor over four evidence classes, not a probability the claim is true. The combiner is explicitly not_fit. Mitigation: always show the four components and which one is binding — never the composite alone.

R4
Two lanes confuse people.

"Cluster 4 is enriched near cluster 7" and "myeloid cells are enriched near neurons" look alike and mean very different things. Mitigation: the lane is a persistent property of every step, every figure and every claim — not a footnote in the report.

MeasurementHow we know it worked

Not sessions, not runs. Time from bundle to first validated claim, and the share of datasets that ever cross the gate. A user who runs the descriptive lane forty times and never unblocks is a product failure that looks like engagement.

Secondary: median time-to-70%-coverage in Review Studio; the fraction of proposed plans a user edits before approving — near zero means the planner is trusted, near one means Ask is theatre; and reviewer agreement on doubly-labelled sections, which is the input the calibrated reliability model has been waiting for.
